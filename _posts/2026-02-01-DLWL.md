# Introduction

Numerous wildlife photographers spend a noticeable of time sorting their
pictures. It often happens that they do not find one animal at a time,
but pictures of the same animals being spread out thorugh their entire
camera roll. Simultaneously, camera traps installed in wildlife
sanctuaries to monitor animal well-being <a href="#UKWUOMA2022e01151">[18]</a>. In both
tasks, an AI model can alleviate the sorting task, as automatic
detection can be achieved. However, such models often have to be able to
run on smaller edge devices, meaning they have to be small and
efficient, taking advantage of the resources it has access to. In order
to compress a model, model compression techniques such as knowledge
distillation and model pruning can be used <a href="#liu-2025">[12]</a>. Therefore, this
paper investigates wildlife detection using compressed models, proposing
a possible alternative to an existing model that is less computationally
expensive, yet, achieving comparable results.

A popular series of object detection models is You Only Look Once (YOLO)
<a href="#yoloPaper">[15]</a>. The original model was praised for removing the need for
multiple evaluations of the input, speeding up inference. Based on this
series, multiple smaller architectures have been proposed for wildlife
detection. This includes:

-   <a href="#BAKANA2024102541">[1]</a>, who suggested WildARe-YOLO, a faster and
    lighter version of YOLOv5s for wild animal recognition. It focuses
    on lower computational costs for model parameters and floating-point
    operations with roughly 5M parameters.

-   <a href="#CHEN2024102791">[5]</a>, who introduced YOLOSAG, an improved and smaller
    version of YOLOV8n (2.6M vs 3M parameters), optimised for the
    detection of wildlife objects.

Furthermore, <a href="#passion_fruit">[3]</a> suggested the YOLOv8-MDN-Tiny model with
promising results in disease detection for passion fruits. Compared to
the original YOLOv8 model, the YOLOv8-MDN-Tiny model has reduced
computation and memory requirements while improving accuracy and speed.
They compress the model architecture by pruning it using the Slimming
algorithm by <a href="#SlimmingAlgorithm">[13]</a>. Then they used a bigger teacher model
to distill the knowledge to the pruned model in order to improve the
accuracy and recover from the degradation of detection performance
during pruning.

All the models above still need post-processing using the Non-Maximum
Suppression Algorithm (NMS) in order to remove duplicate predictions.
More recent models such as YoloV10 and Yolo26 remove the need for this
final preprocessing step allowing for more efficient inference. More
recently, Pytorch Wildlife by Microsoft <a href="#torchwildlife">[9]</a> launched a
project hosting multiple models of various sizes for wildlife detection
such as the MegaDetector series. One of them includes a small pretrained
version based on the Yolov10 architecture with only 2.3M parameters.

In this project, we aim to improve the performance of the small
pretrained MDV6-yolov10-c model by distilling knowledge from the
pretrained YOLO26l model. We will use this as a recovery technique after
applying strucutred pruning to the MegaDetector model, as inspired by
<a href="#passion_fruit">[3]</a> using the YOLOv8-MDN-Tiny model.

Whilst the concepts introduced are not novel, the idea of combining
knowledge distillation, pruning and the YOLO26l and MDV6-yolov10-c
models has not yet been explored in the literature.


## Knowledge Distillation

Knowledge distillation involves distilling knowledge from a bigger model
or a model ensemble (the teacher) into a single smaller model (the
student). For distillation in classification tasks where the model
produces class probabilities using softmax, one can match the soft
targets produced by the teacher and the student <a href="#distill">[10]</a>. Then the
loss function is often composed of a weighted cross entropy loss and the
Kullback-Leibner distance between the soft output distributions produced
by the teacher and the student model <a href="#distillLoss">[2]</a>. A hyperparameter
$T$ is used in order to control the "softness\" of both predicted
distributions by dividing the output logits by $\tau$ before being
transformed to class probabilities using softmax. During inference
$T=1$.

In order to distill localization knowledge (i.e. where an object is in
the image), a regression loss (such as a variation of the IoU
<a href="#localDistill">[21]</a>, we make use of Complete IoU) between the predicted
boxes can be used with an upper bound <a href="#Upperbound">[4]</a>, where the
distillation loss is not used when the students performs better then the
teacher. Adding this localization knowledge is more efficient than only
mimicking class predictions.

However, this prediction mimicking approach can suffer from a conflict
between the ground truths and the distillation targets from the teacher
(when no upper bound is applied in case of localization). In order to
mitigate this issue, cross-head knowledge distillation can be used
<a href="#crossKD">[20]</a>. An intermediate feature from the head of the student is fed
to the rest of the head from the teacher after which a prediction is
made. The objective is to match this with the teacher's original
predictions. This type of distillation is going to be explored further
in this project.

An alternative is hint-based knowledge distillation where the student
has the objective to mimic the feature space of the teacher
<a href="#hintbased">[16]</a>. A regression loss between the two feature spaces is used
and a small regressor is added to the student's feature extractor in
order to match the two spaces. We will not focus on this kind of
knowledge distillation in this project, but it would represent an
interesting topic to be tackled in the future.

# Methodology

## Datasets and preprocessing

This project focuses on classification and detection of animals. For
this, we use the OpenImages Dataset V7 <a href="#openimages">[14]</a>. This dataset was
chosen because of its high versatility, covering over 300 classes, from
which we extracted 14 classes containing animals as seen in [Table 1](#table_1). The bounding boxes are initially saved as
$(X_{\min}, X_{\max}, Y_{\min}, Y_{\max})$, and are converted to
$(X_{\text{center}}, Y_{\text{center}}, \text{Width}, \text{Height})$ in
order to fit the required format compatible with the ultralytics
package, allowing us to use the YOLO models.

Initially, the training split has 13986 samples with a the total number
of 22389 animals, where multiple animals can appear in a single file,
having one unique label or different unique labels. It can be noticed
that the classes are highly imbalanced, as showcased in [Table 1](#table_1). We mitigate this by both undersampling and
oversampling. Undersampling randomly deletes 200-1000 files from
majority classes that appear over 3000 times in our training dataset.
The degree of oversampling of the minority class was based on the
difference between the number instances in the majority class and the
minority class. Oversampling an image from a class instance was done by
selecting a file in the training set with a probability of 0.7, and
applying one augmentation. This process is repeated until the desired
number of transformations per class was achieved. For heavily
undersampled classes ($<$ 1000 instances), this probability is 1. The
augmentations used are BGR to RGB, greyscale conversion, adding Gaussian
noise, and brightness, contrast, saturation and hue adjustments. The
under- or oversampling was applied on files containing only one animal
class in order to easily control the number of instances in comparison
to the other classes. Ultimately, the percentage of total instances of
the majority class were brought to under 10%, while the minority classes
consists of 6% of the training data. The validation and test splits were
not altered in this process. We ended up with 20470 files, representing
31890 animal instances in total.

## Models

We will perform knowledge distillation with models based on two
different architecture. Our student will be the MDV6-yolov10-c model
from <a href="#torchwildlife">[9]</a>. This is the smallest pretrained model based on
the YOLOv10 architecture available in this framework, with 2.3 million
parameters. We use the YOLO26l architecture as the teacher, with a total
count of 24.8M parameters. Both models are illustrated in [Figure 2](#fig:yolo-models). It is
important to note that the most layers in the teacher model are wider
compared to the student. Sometimes, these modules are also stacked,
increasing the models depth. As these models also differ in their
architecture, they use different modules. Such a module is the PSA and
the C2PSA. The difference is illustrated in [Figure 3B](#fig:psa), where it can be
noticed that the C2PSA module includes two PSA modules with two
additional convolution layers. Another notable difference in the YOLO26
architecture is that they use C3K2 modules instead of C2F as seen in [Figure 3A](#fig:c3k2), where
it is emphasized that the C3K2 stacks multiple C3K layers. Both these
differences illustrate an increase in the depth of the modules, which
can increase the size of the models and improving their performance.

## Distillation

We experiment with both class and localization knowledge distillation
(KD), applying cross head distillation (cross head KD) or no cross head
distillation. We define $N$ as the number of samples, $C$ as the number
of classes, *T* as the temperature, $p$ as the probability of a class
being chosen as the final result, $t$ as the teacher and $s$ as the
student. We define the classification distillation loss as the mean KL
divergence over batches for student ($z^s$) and teacher ($z^t$) logits,
$$
\mathcal{L}_{\mathrm{cls}}
=
T^2
\frac{1}{N}
\sum_{i=1}^{N}
\sum_{c=1}^{C}
p^t_{i,c}
\log
\frac{p^t_{i,c}}{p^s_{i,c}},
$$

where

$$
p^t_{i,c} =
\frac{\exp(z^t_{i,c}/T)}
{\sum_k \exp(z^t_{i,k}/T)},
\quad
p^s_{i,c} =
\frac{\exp(z^s_{i,c}/T)}
{\sum_k \exp(z^s_{i,k}/T)}.
$$

In order to distill localization knowledge, we calculate the CIoU for
both the student $s$ and the teacher $t$ with respect to the ground truth
$gt$, using the bounding boxes $\mathbf{b}$:

$$
\mathcal{L}_{s/t,gt}(i)
=
1 - \mathrm{CIoU}(\mathbf{b}^{s/t}_i, \mathbf{b}^{gt}_i).
$$

We use this to determine the upper bound and create a mask $\mathcal{M}$
to determine when the student is performing better than the teacher:

$$
\mathcal{M}
=
\left\{
i \in \mathcal{N}
\;\middle|\;
\mathcal{L}_{t,gt}(i)
<
\mathcal{L}_{s,gt}(i)
\right\}.
$$

This mask is applied to the CIoU loss comparing bounding boxes
$\mathbf{b}$ predicted by the student and the teacher within the batch:

$$
\mathcal{L}_{\mathrm{IoU\text{-}KD}}
=
\frac{1}{N}
\sum_{i \in \mathcal{M}}
\left(
1 - \mathrm{CIoU}(\mathbf{b}^s_i, \mathbf{b}^t_i)
\right).
$$

The final KD loss is the sum of both losses:

$$
\mathcal{L}_{\mathrm{KD}}
=
\mathcal{L}_{\mathrm{cls}}
+
w_{KD} \cdot \mathcal{L}_{\mathrm{IoU\text{-}KD}},
$$

and the total training loss is

$$
\mathcal{L}_{\mathrm{total}}
=
\mathcal{L}_{\mathrm{det}}
+
w_{KD2} \cdot \mathcal{L}_{\mathrm{KD}}.
$$

where $\mathcal{L}_{\mathrm{det}}$ is the standard YOLO detection loss
defined in <a href="#yoloGithub">[11]</a> and

$$w_{KD2} = 1 - 0.45 \left( 1 - \cos\!\left( \frac{i\pi}{|\mathcal{D}_{\text{train}}|} \right) \right).$$
was derived from <a href="#githubdistill">[6]</a>. This dynamically adjusts the weight
attributed to the KD loss during the training process <a href="#cosweight">[19]</a> based
on the training step *i*. $w_{KD}$ is manually selected after
investigating the loss term values.

When performing cross head KD, we do not apply $\mathcal{M}$ as both
outputs are derived from the teachers head. We perform the cross head KD
with the modules indicated by the red arrow in [Figure 2](#fig:yolo-models). Before we feed the features from the student to
the teacher, we feed the features to a smaller regressor with learnable
weights and a 1x1 convolutional kernel to upsample the number of
channels to 512, as that is the input expected by the C3K2 module of the
teacher.

After analyzing runs with the student, we discovered that the weight IoU
loss was significantly smaller in magnitude than the classification
distillation loss. To ensure that the losses had the same magnitude, we
set the weight of *w$_{KD}$* to 100 for the non-cross head KD and 10 for
the cross head KD.

## Training setup

For all the models trained, we determine a set of augmentations to be
performed on the samples during training. With a probability of 0.5, the
following transforms could be conducted for each image: brightness,
contrast, saturation, hue and value adjustments, adding Gaussian blur,
and horizontal and vertical flip. This suggests that more augmentations
could be applied to the same image.

First, the pretrained teacher is trained on the processed OpenImages
dataset for 50 epochs, with batch size of 16. The student model was also
trained on the dataset, without any guidance from the teacher, in order
to compare its performance with the distilled counterparts.

With the fixed trained teacher model, the student model was trained for
50 epochs using non-cross head KD. The hyperparameter search was
conducted using Optuna to tune the temperature *T* in the KL divergence
computation, over 20 epochs, due to computational resources and time
constraints. The search optimized the mean average precision with
threshold 0.5 IoU (mAP50) on the validation set. Five trials were
carried out, sampling *T* from the range \[1.0, 10.0\]. The optimal *T*
value proved to be 1.005.

Ultimately, two student models were trained for 50 epochs using the
optimal *T* with the non-cross head KD or the cross head KD. There was
no pruning applied, as we did not manage to implement this
functionality.

The code was adapted from <a href="#yoloPaper">[15]</a>, and modified in order to fit the
implementation described previously.

# Results

[Figure 4](#trainresults) displays the monitored losses and metrics
on the train and validation sets over 50 epochs when training the
YOLOv26l and MDV-YOLOv10-c models. It can be seen that the validation
loss has plateaued for both the teacher and the student whilst the
training losses are still decreasing. We notice a slight increase in the
validation loss for the student in the last epochs, indicating that the
model could possibly start to overfit from this point. Longer training
until convergence would be necessary in order to fully investigate this
behaviour. We did not try to train for at least double the epochs
because of time-constraints and limited computational resources, as the
Habrok waiting times were a bottleneck in debugging and running
experiments.

Furthermore, the teacher model displays lower loss values and higher
scores for recall, mAP50 and mAP50-95 compared to the student. This
indicates that, indeed, a bigger model performs better on our dataset.
We aimed to decrease this gap using KD. [Figure 5A](#w_KD) displays
how the metric changes during the training process when applying our
distillation loss. Although mAP increases slightly quicker at the
beginning of the training, it does not appear to perform better than
when KD is not used. Furthermore, the increase in precision and recall
seems slightly smoother during the training process when using KD. This
does not seem to be the case when using cross head KD as seen in [Figure 5B](#w_crossKD). This
method also reaches similar performance to the other versions of the
trained student model. Similarly to the other students, it does not yet
match the performance of the teacher.

When visually inspecting a batch of predictions we do note a difference
between the teacher ([Figure 6A](#fig:example-a)), the student ([Figure 6B](#fig:example-b)) and the student trained with non-cross head KD ([Figure 6C](#fig:example-c)). The student trained with KD makes
different mistakes compared to the student trained without KD. When
looking at the picture of the snake, tortoise, rhinoceros (top right)
and the image with the three monkeys, it can be noticed that the
confidence of the predictions closely matches the teacher, calibrating
the predictions. When cross KD is applied it is also able to detect one
more monkey, as depicted in the second image from the second row.

The biggest discrepancy is in the image with the three drawn crocodiles
at the bottom left. The teacher is able to correctly detect all three
crocodiles. The student without KD is only able to distinguish two, and
when trained with KD it classifies the entire image as one crocodile. We
cannot conclude that the student matches the teacher more closely in the
confidence of its predictions when trained with cross head KD. 
Furthermore, after inspection of the classes on the test said we observed that all models find it most difficult to distinguish leopards and cheetas.

Furthermore, we can deduce that the teacher model performs better than
all variations of the student model, with no staggering differences
between these variations. This pattern is especially visible when
analyzing the results on the testing set, depicted in [Table 2](#table_2).

# Discussion

Whilst KD is a technique where knowledge from the teacher is distilled
into a smaller student in order to improve the performance of that
student, we did not see an increase in our performance. metrics.
Furthermore, we tested both cross head KD and the non-cross head KD,
concluding that their performance does not largely differ. This is
contrasting the claim of <a href="#crossKD">[20]</a>, where it is stated that it is
possible to achieve better results using cross head KD compared to
non-cross head KD. Notably, this effect may also be model-dependent. For
instance, the discrepancy in dimensionality between the student module
from which features were extracted and the teacher module into which
they were injected may have been too large. Moreover, we did not explore
alternative regressors for mapping the student features to the teacher
feature space, nor did we evaluate different injection points, which
limits the scope of our observations. Hence, exploring these ideas
further would be interesting for future projects.

As suggested by <a href="#passion_fruit">[3]</a>, KD can be beneficial for helping a
model recover after pruning. This may be a scenario in which the
implemented methods could have provided greater benefits compared to
standard training procedures. However, as noted in the Methods section,
this was not feasible within the scope of this project. Consequently,
this question is left to future work within the experimental settings
described in this project.

Additionally, we initially aimed to focus on isomorphic structured
pruning <a href="#isomorphicpruning">[8]</a>. This approach identifies substructures
using computational topology---specifically by constructing a dependency
graph of the model, and applies importance ranking within these
structures. As a result, it mitigates the risk of excessively pruning
specific layers, a limitation often observed in global structured
pruning. Our intention was to use the DepGraph to identify dependencies
and apply pruning accordingly <a href="#depgraph">[7]</a>. However, we were unable to
successfully implement isomorphic pruning using the torch-pruning
library. Despite being more challenging to implement than local pruning,
this approach represents a promising direction for future research.
