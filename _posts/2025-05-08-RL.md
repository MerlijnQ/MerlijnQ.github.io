# Abstract

This paper examines the performance of various Deep Reinforcement
Learning methods when applied in the game of Catch. We implement Deep
Q-Learning (DQN), Double Deep Q-Learning (DDQN), which rely solely on
estimating the state-value function $Q$; Deep Quality Value (DQV) and
DQV-Max, which leverage the value function $V$ alongside estimation of
$Q$; and the Dueling Architecture, which learns the advantage function
$A$ and the value function through two separate streams. Over five
different runs per model, all implementations achieve a mean success
rate of at least 85% after 30,000 updates. The DQN and Dueling DQN show
the best performance, reaching 96% and 97% respectively. The results
show that the simpler models, such as DQN, can outperform more complex
models in the Catch environment. Furthermore, separating between the
value of a state and the advantage of an action has been found to be
beneficial, as shown by the Dueling Architecture. Lastly, a limitation
of these compute heavy algorithms is difficulties with extensive tuning,
which could potentially lead to suboptimal solutions. A demo of the
performance of the various trained models can be seen in the following
[video](https://youtu.be/RWHy-8QiVyk).

# Introduction

Everyone has played it as a child. With only a ball, you entertain
yourself and your peers by throwing and catching it. In a video game
environment, a game of catch consists of a paddle at the bottom of a 21
x 21 grid environment where an agent can choose to move it left, right
or abstain from moving it. A ball will be falling down, which can
potentially bounce off the wall, which the agent has to catch with their
paddle. This is not only a game suitable for an arcade, but also for
testing deep learning models in dynamic environments, in a less expensive way compared to bigger benchmarks based on Atari games, as first
introduced by <a href="#mnih2014recurrentmodelsvisualattention">[4].

The game of Catch can be represented as a Markov decision process where
the state space ($\mathcal{S}$) consists of all the possible position
combinations of the paddle and the ball, the action space
($\mathcal{A}$) contains all the possible movements (or lack thereof).
The transition function ($\mathcal{T}$) represents the deterministic
physics of the environment and the reward function ($\mathcal{R}$),
which gives a positive signal when the ball is successfully caught.
Using this, a policy can be created defining the probability of an
agent's action ($a$) given a state, in order to maximise the received
reward, which is weighted by a discount factor $\gamma$. The latter
allows to describe how favourable it is to be in one state compared to
another, as summarised by a *value* (*V*). For example, it would be more
favourable to have my paddle close to the ball, where only slight
movement is required, compared to being far away, increasing the risk
you might not catch it. The value can be conditioned on the actions
defining the quality (*Q*). To find the optimal policy, we find a value
function that returns the maximum value given the states, and the
maximum Q-value given all state-action pairs.

In very large state action spaces, it is not feasible to define such a
policy using a simple table in which an agent records its observations.
An alternative approach to overcome this issue is to let a neural
network approximate the optimal policy using Deep Q-learning. There are
multiple solutions available on how to do this, which have been shown to
be able to complement each other <a href="#ref-rainbow">[2]</a>. In this paper, we will
cover five of these solutions and investigate how these compare in
playing the game of Catch.

## Solutions

In this section, we introduce the solutions investigated in this paper.

### DQN {#DQN}

The first algorithm we adopt to play the game of Catch is the Deep
Q-Network (DQN). This approach was first described in the seminal work
on playing Atari games with deep reinforcement learning
<a href="#mnih_playing_2013">[3]</a>. The DQN algorithm is different from classical Q-learning because it uses a deep neural network, parametrized by
weights $\theta$, to approximate the action-value function
$Q(s, a; \theta)$.

Because learning directly from consecutive sequential samples is
unstable due to temporal correlations, DQN utilizes experience replay. At each time-step, the agent's transition $e_t = (s_t, a_t, r_t, s_{t+1})$ is preserved in a finite-size replay
memory buffer $\mathcal{D}$. During learning, network updates are
applied over minibatches of experiences.

The network is trained with the following loss function:

$$\label{eq_DQN}
    L(\theta) = \mathbb{E}_{(s_t,a_t,r_t,s_{t+1})\sim\mathcal{D}} \left[ \left( y_t - Q(s_t, a_t; \theta) \right)^2 \right].$$

The target 

$$\label{eq:DQN_target}
    y_t = r_t + \gamma \max_{a \in \mathcal{A}} Q(s_{t+1},a; \theta^-)$$

is computed using a separate target network. The target parameters
$\theta^-$ are held fixed during training and are only synchronised
periodically with the online network weights, which makes the problem
more stationary.

### DDQN

In the standard DQN setting, we use the same set of weights to both
choose the best action and estimate its value. By iteratively picking
the maximum of these estimated values, the algorithm learns to
approximate the expected maximum value, instead of the maximum expected
value. This behaviour leads to overestimating the value of certain
state-action pairs.

To amend this, Double Deep-Q Learning (DDQN) was introduced by <a href="#ddqn">[7]</a>.
DDQN works by decoupling the underlying weights used for selection of
actions and evaluation by exploiting the usage of the online network
$\theta$ and target network $\theta^-$ as presented in the DQN model.
$\theta$ is used in the action selection process, and $\theta^-$ is used
to evaluate the quality $Q$ of the given actions. Similar to DQN, the
online network receives the updates at every single training step
through gradient descent methods, while the target network is not
directly trained. Instead, its weights are periodically copied from the
online network. The loss function for DDQN is identical to the DQN loss barring the target formula, which is given by:

$$
y_t = r + \gamma Q\left(
s_{t+1},
\arg\max_{a \in \mathcal{A}} Q\left(s_{t+1}, a; \theta\right),
\theta^{-}
\right)
$$


In contrast to the DQN target formula from Equation 2, we observe that the online network is used
solely for selecting the action to evaluate, which is evaluated with
respect to the target network. It is of note that DDQN also strays away
from the structure of its shallow namesake, Double Q-Learning
<a href="#NIPS2010_091d584f">[1]</a>, where at every update, one of the two networks is
picked stochastically to be trained.

### DQV

In contrast to the Deep Q-network, the Deep Quality Value (DQV) Network
<a href="#dqv">[5]</a>, utilises the State-value function as an extension of the
action-value function. Hereby, the model learns two separate networks
that learn from each other in the training process, each split into an
online and a target network, totalling four networks. In DQV-learning,
the State-value function is learned via the following loss,

$$
L(\Phi) =
\left(
r_t + \gamma V(s_{t+1}; \Phi^-)

* V(s_t; \Phi)
  \right)^2
  $$

and the Action-value function via the following loss,

$$
L(\theta) =
\left(
r_t + \gamma V(s_{t+1}; \Phi^-)

* Q(s_t, a_t; \theta)
  \right)^2
  $$


In these two loss functions, it can be seen that both rely on the same
TD-target: $y_t^\theta = r_t + \gamma V(s_{t+1}; \Phi^-),$ which is the
reward at the current time step plus the approximate value of the next
state using the target network multiplied by $\gamma$. The network of
the approximator for the value function is updated by minimizing the
squared loss between the TD-target and the current approximate value of
the state. Whereas, the network for the action-value function minimizes
the squared loss between the TD-target and the approximated
action-value.

### DQV-Max

Similarly, the DQV-max algorithm <a href="#dqv">[5]</a> utilizes both the value function
and the action value function. However, the difference is that this
network uses a different TD-target. In this algorithm, the approximator
for the value-function uses the following TD-target,

$$y_t^\Phi = r_t + \gamma \max_{a} Q(s_{t+1}, a; \theta^-)$$

which is the current reward plus the maximum action-value of the next state
multiplied by $\gamma$. Similarly to the DQV-network, the action-value
function is learned using the same TD-target defined as follows,
differing only in the fact that it uses the online variant of the value
function approximator: $$y_t^\theta = r_t + \gamma V(s_{t+1};\Phi).$$

Resulting in the loss function for the approximator for the value
function of: 

$$
L(\Phi) = \left(r_t + \gamma \max_{a} Q(s_{t+1}, a; \theta^-) - V(s_t; \Phi)\right)^2,$$

and the loss function for the approximator of the action-value function
of:

$$
L(\theta) = \left(r_t + \gamma V(s_{t+1}; \Phi) - Q(s_t, a_t; \theta)\right)^2.
$$

The benefit of both the DQV and DQV-Max algorithms over the deep Q and
double deep Q networks is that these have faster convergence and overall
better performance, which can be the result of the model's ability to
reach better value estimates. Furthermore, both these networks have
fewer issues with overestimation bias. This is due to the model
utilizing both the value and action-value functions, which depend on
each other in the learning phase.

### Dueling Architecture

The solutions above are constrained to learning each action for each
state without being able to evaluate which states are useful separately.
An action would not influence the environment. In the game of Catch,
this would be the case when there is no reason to move the paddle yet.
Therefore, <a href="#DuelingNetwork">[8]</a> proposes to separate the network output into two streams. One stream will evaluate the value of a state denoted as
$\beta$, whereas the other approximates the advantage function ($A$)
denoted as $\alpha$. The latter describes how much better one action is
over another and is related to the quality and value according to the
following equality: $A^\pi(s, a) = Q^\pi(s, a) - V^\pi(s)$. The
approximations of the value and advantage functions by the network are
aggregated as follows in order to estimate the state-action pair values
given a parametrized model with parameters $\theta$:

$$\begin{aligned}
Q(s, a; \theta, \alpha, \beta)
&= V(s; \theta, \beta) + (A(s, a; \theta, \alpha) \\
&\quad - \frac{1}{|\mathcal{A}|}
\sum_{a_0} A(s, a_0; \theta, \alpha))
\end{aligned}
\label{eq:Dueling}$$

This allows the network to adjust the state value during training
without significantly affecting the advantage values. The advantage is
offset by its mean. Alternatively, this can be replaced by a max
operator, which allows us to recover $A$ and $V$ uniquely from $Q$, as
$A$ will be zero at its chosen action. However, the offset using the
mean results in smaller changes and therefore more stable optimization
instead of having to compensate for any change to the optimal action
advantage as argued by <a href="#DuelingNetwork">[8]</a>.

# Methods

In this section, we introduce technical considerations made with regard
to the overall implementation of the experiment and the agents. This
excludes the Catch environment in which the agents learn, which is
described at the start of the introduction.

## Exploration Strategy

During training, the agents follow an $\epsilon$-greedy strategy to
balance exploration and exploitation. At a given timestep, a random
action is chosen with probability $\epsilon$, allowing the agent to
explore its environment. Otherwise, the agent exploits the current
policy it has learned. The exploration rate is linearly annealed over a
fixed number of frames in the bounds \[1.0;0.01\], and is held fixed
thereafter <a href="#mnih_playing_2013">[3]</a>.

## Prioritized Experience Replay

In order to let a deep reinforcement agent learn from past experiences,
we sample them from memory to use during training. The most basic
approach is to do this uniformly, which disregards their significance.
To address this issue, <a href="#PER">[6]</a> introduced prioritized experience replay (PER). This approach records the temporal difference per sample per
forward pass, which is their priority $p_i$. At every sampling step, the
recorded priorities can be translated to probabilities using
$$P(i)=\frac{p_i^\alpha}{\sum_{k}p_k^\alpha}$$. Here $\alpha$ determines
the degree of prioritisation. As this introduces bias by changing the
distribution (which changes the solution the model would otherwise
converge to), this needs to be corrected by importance sampling weights
used by the loss function: $$w_i=(\frac{1}{N*P(i)})^\beta$$, which
should be normalised by the maximum weight. Here, $\beta$ determines the
degree of compensation for non-uniform probabilities, which is at its
maximum when $\beta=1$. We use PER for all tested solutions with
$\alpha=0.6$ and $\beta=0.4$, which were found to perform best in the
original paper. Lastly, we apply a linear annealing schedule to $\beta$
until 1 over the $\epsilon$ decay window. This allows the model to focus
on harder samples more at the start, but consider the entire original
distribution before converging to its final policy.

## Implementation Details

#### Network Architecture

Unless otherwise stated, all models use the same neural network
architecture. The specific parameters are derived from the model
presented in <a href="#mnih_playing_2013">[3]</a> and illustrated in [Figure 1](#fig:architecture). The network takes 4 stacked grayscale
frames of size $84 \times 84$ as input. The architecture consists of two
convolutional layers, followed by two MLPs. The relatively large stride
allows the network to rapidly downscale the input while retaining a
large effective window. The last layer of the network consists of as
many neurons as actions, in our case, 3. All network parameters in our
experiments are optimised via RMSProp. In addition, we use Huber Loss,
which is corrected using the importance sampling weights.

#### Dueling

We train the Dueling architecture according to the same process
described for DDQN. We add one dense hidden layer with an output size of
256 units for both the value and advantage streams after the two
convolutional layers described above. This is followed by another dense
layer with one output unit for the value stream, whereas this is defined
by the number of possible actions for the advantage stream. Their
outputs are aggregated as described in the introduction.

## Evaluation Metrics

As noted by <a href="#mnih_playing_2013">[3]</a>, computing the average episodic reward
during training can be very noisy. To address this issue, we use a
strategy similar to the original work. Firstly, a fixed, held-out set of
20,000 states is collected by following a random policy prior to
training. During training, we compute the average maximum $Q$-value over
the hold-out states. This gives us a smoother estimate of the discounted
reward the agent expects to obtain. Secondly, we evaluate the agent's
absolute performance by having it play 100 games in a separate
environment. During these games, the exploration rate $\epsilon$ is set
to 0.05 such that the agent exploits its learned policy
<a href="#mnih_playing_2013">[3]</a>. We then record the mean score of the agent across
the 100 games. Both metrics are computed after every 1,000 network
updates. Lastly, we compute the average loss for every 1,000 network
update segments.

## Hyperparameters

#### Common Settings

For each model, we perform hard updates with $\tau=1$. This means after
a certain number of updates, the target net will be updated in its
entirety with the weights of the online net without preserving its old
weights. The alternative is to update the target network more often with
small updates. We decided not to do this and focus on the remaining
hyperparameters instead. In this setting, we see the online net move
towards a stable target, which can be easier to train than a moving
target. For the game of catch, this appears to be sufficient, as seen in
the results section.

We will test all algorithms over 5 runs with 30,000 network updates.
This number was selected because the models' performance tends to
plateau, leading to diminishing returns for any additional training
updates. We demonstrate this in [Figure 2](#fig:deminishing)
for the Dueling architecture over a single run.

The batch size is kept at 64, momentum at 0.95, gamma at 0.99. Training
starts after 1,000 iterations of exploration.

# Results

[Figure 3A](#fig:mean_reward) displays how the different solutions behave
over 30,000 updates, measured every 1,000 updates over 100 games. We
observe that DQN, DDQN and their Duelling versions manage to reach the
highest scores, fluctuating between 0.9 and 1.0 after approximately
18,000 updates. Furthermore, DQV performs worst compared to the other
solutions with relatively unstable training due to a large variance
across runs. The latter is also prominent for DQV Max.

Similar observations can be made with ragard to the mean max Q value
over the 30000 updates as seen in Figure
[Figure 3B](fig:mean_q).
Duelling DQN and DQN achieve much larger Q values, demonstrating that
those algorithms are more certain in their choice of action. These
values increase faster for DQV max at the start of training, which means
it learns faster, but this stagnates early as well, preventing it from
achieving similar performance to Duelling DQN. DQV itself shows the
slowest increase in mean max Q-value. Lastly, DDQN and Duelling DDQN
perform similarly, with mean max Q values reaching roughly 0.8 after
30,000 updates. The Duelling version demonstrates slightly faster
learning performance and a smaller difference across runs in later
updates.

# Discussion

The comparison of the different algorithms shows that the Duelling DQN
model performs best, closely followed by DQN, DDQN and its Duelling
version. Even though DQN is the simplest algorithm we compare, it is
still competitive with respect to the more complex alternatives in this
simple setting, which is the game of Catch. Possibly, its performance
can be attributed to the simple environment, as the number of states and
actions is limited compared to more complex real-world environments.
Likely for the same reason, the performance of the majority of the
algorithms is relatively similar.

Furthermore, the Duelling architecture showed some improvements for DQN
and DDQN. This indicates that it is beneficial to let the model separate
between the value of a state and the advantage of one action over
another, given a certain state, as learned by their respective streams.
This resulted in the best-performing model.

However, we did not expect DQV and DQV max to perform considerably worse
than the other algorithms. This includes the slower and less steady
increase of Mean scores and Mean Max Q-values. As seen in [Figure 3](fig:performance), these metrics did not finish increasing
when we stopped training the models at 30,000 updates, meaning the
models did not converge yet. This means that with considerably more
training, they could have reached higher scores similar to the other
algorithms. However, as this makes them more expensive to train, the
alternatives are favorable. Both DQV variants were trained with a
considerably higher learning rate compared to the other models. This,
and the other hyperparameters, were tuned by hand to find a setting that
was stable across runs with increasing Q-values and increasing mean
scores. This tuning procedure marks a clear limitation of our study. It
is a result of limited available compute during training, hindering our
ability to do an extensive hyper-parameter search. Therefore, we cannot
exclude the possibility that there exist better hyperparameters that
would shift the performance of the models in DQV's favor.
